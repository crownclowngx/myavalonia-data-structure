# 设计与再次审核

## 深浅主题

原 View 使用 `RequestedThemeVariant="Light"`，同时为普通控件和两个自绘控件指定了固定浅色。
本次移除主题强制作用域，由逻辑祖先传入实际主题。没有增加 Document 主题字段或全局切换器。

`AcThemeResources` 在本域 View 的资源中提供 Light/Dark 语义画刷：页面、卡片、正文、
辅助文字、输入、公式、选中与警告等。控件使用 `DynamicResource`，不把资源注册到 Application。
普通控件的焦点、悬停、禁用及弹出层继续由 Host 使用的 Avalonia 主题模板处理。

自绘的 `AutomatonCanvas`、`TextTape` 通过一个 StyledProperty 接收不可变的 `AcDrawingPalette`。
主题字典切换此属性，`AffectsRender` 立即重绘；布局、平移、缩放及 Document 的轨迹不重建。
当前节点使用深青底白字，暗色背景上的强调线用亮青；失配、候选和命中沿用暖色语义。
颜色常量集中在两套主题资源中，不在 Render 中反复解析十六进制颜色。

## 单步构建与匹配

算法原已记录逐节点插入、BFS fail 和逐条命中。原界面把单步入口放在窗口底部，统计只显示
最终状态总数；扫描每次回退后的边比较也没有独立步骤，容易让使用者误认为直接展示最终结果。

- 在画布旁增加重建、上一步和下一步，按钮提前说明下一动作，例如长出节点、比较字符、输出一条结果。
- 统计改为“已长出 x / y 个状态”，显示当前前缀深度、正在比较的字符和已输出数量。
- Trie 保持真实的按词逐字符插入，共同前缀复用；节点、词尾、fail 和结果只在各自事件到达时出现。
  这不是把逐词 Trie 插入改成 BFS；BFS 用于下一阶段按层构建 fail。
- 新增纯领域事件 `Compare`。每次边查询先记录比较结果，下一步才转移或回退；
  沿 fail 后再次比较同一个字符，只有转移事件消费文本。同一位置的多个输出各占一步。
- 阶段跳转、下一次命中和扫描至结尾保留为显式快进；默认应用输入停在只有根节点的起点。

## SOLID 与审核结论

主题只在呈现层处理，领域层和播放层没有引入 Avalonia 依赖；比较事件由轨迹构建器产生，
View 只投影它，不自行运行匹配算法。Document 负责交互命令及说明文字，已有时钟接口保持最小。
没有新增工厂、主题策略接口、跨算法基类或可变共享状态。新注释使用中文说明资源所有权、
即时重绘和比较事件的执行顺序。

检查了提前显示、回看撤销、同字符多次 fail、同位置多结果、切换主题保留播放和跨域资源泄漏。
真实像素检查能发现只换主题属性而未重绘的问题；随机对照仍覆盖匹配结果和最长后缀不变量。
新事件增加教学步骤，仍受 12,000 步预算限制；快进功能需要使用者显式触发。
